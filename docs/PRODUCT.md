# 澄川 Chengchuan：产品规划

状态：2026-11-02建立。定位：个人桌面的专业股票研究工作台，优先Windows和Linux。

## 名称与产品方向

中文名「澄川」，英文标识「Chengchuan」。“澄”代表清楚、可核查，“川”代表持续流动的行情。名称和版本集中在`chengchuan/__init__.py`，可统一调整。

核心体验：**打开股票，看清走势，选中一段，得到可以复算的特征和证据，再与其他区间比较。**

长期目标是在键鼠操作、图表响应、布局保存、数据质量和研究效率上达到专业桌面软件的使用感。功能按完整使用链路逐步交付，避免页面很多却没有可靠研究闭环。

## 常用工作流

1. 从自选、股票代码或搜索打开股票，选择周期和价格口径。
2. 看K线、成交量、均线及指标，图表缩放和时间轴联动。
3. 按Ctrl拖选时间段，松开鼠标后计算基础特征和阶段候选。
4. 查看支持证据、反向解释、数据覆盖及不可识别项。
5. 保存选区和注释，与另一时间段或另一股票比较。
6. 在历史回放中复现当时可知的信息，评估信号与后续表现。

## 功能地图

| 功能域 | 基础能力 | 后续扩展 |
|---|---|---|
| 行情与资产 | 代码搜索、自选、日K、分时、成交量、状态提示 | 真正分钟K线、更多市场、稳定实时源 |
| 图表操作 | 十字光标、平移缩放、Ctrl选区、快捷键 | 多图联动、画线、事件标记、多屏布局 |
| 区间研究 | 量价统计、相对强弱、阶段证据、数据质量 | 区间对比、特征注册、筛选条件、批量研究 |
| 研究记录 | 选区、注释、工作区、数据与算法版本 | 研究项目、标签、可分享的复算包 |
| 模型评估 | 当前透明规则基线、价格结果观察 | 滚动验证、参数实验、概率校准、真实执行标签 |
| 短周期预测研究 | 相对量、价格位置、固定阶段特征、H1/H2方向和历史逐日对照 | 公司行为核对、多股多年封存及校准，通过后启用概率 |
| 逐笔研究 | 数据字段与授权评估 | 委托还原、撤单分析、执行簇、经验证的金额估计 |
| 公司与事件 | 来源和披露时点的设计预留 | 公告、调研、业绩、股东披露与图表对齐 |

“机构身份”“资金净持仓”和“交易意图”分别有识别条件。GUI中不把大小单分类命名为已确认的机构增持；未校准评分不能显示成概率。

## 当前交付状态

### 已实现的0.2行情工作台

- 桌面窗口、现代深色主题、可调整三栏布局。
- 从旧版标准JSON快照加载日K或分钟采样分时，搜索本地快照名称／代码。
- 成交量副图、十字光标、时间轴、平移缩放。
- Ctrl左键拖选、调整选区边界、Esc清除，右侧显示同一引擎的区间结果。
- 界面外执行加载和分析；一个运行任务加一个待执行任务，待执行项可被更新请求替换。
- 有界分析结果缓存、工作区分栏与选区保存、错误日志。
- 原始CLI保留，新GUI通过适配器复用旧分析内核。
- 沪深A股名称／代码／拼音联网搜索、六位代码直接打开、自选增删与拖动排序并持久化。
- 最新公开报价、日K与分钟采样分时，手动刷新及可暂停的每15秒自动轮询。
- 按股票和周期缓存；显示报价时间、图表覆盖和取得时间，明确旧报价、历史缓存与失败。
- 网络请求在可终止进程中执行，切股立即清空旧图表和分析，刷新同股保留缩放与选区。

当前公开源轮询可能延迟，没有交易所逐笔实时推送或实时订阅。完整证券目录、周K、多源回退、
复权切换、完整分钟K线、公式编辑器、历史回放、Level-2还原尚未实现。日K源缺少成交额，
成交额和VWAP明确缺失；在线图表尚未获取基准及订单金额分类。

### 当前迭代与下一步

输入代码／名称、后台获取、切图和区间研究已经连通。用户授权优先开发短周期预测，0.3已交付下面的研究切片。M1的数据源、周K和时间范围，以及盘中连续刷新验证仍列为未完成项。

验收要求：股票切换正确；缺失、过期和失败可区分；图表不会把分钟采样价当作真实分钟K线；界面不因网络请求失去响应。

### 0.3：量价位置与阶段联合预测研究

2026-11-04已实现。联合今天相对昨天／前两日及5／20日基线的成交量、20／60日价格位置、涨跌和收盘结构、固定窗口阶段评分，用过去成熟样本研究未来一个、两个交易日的方向。

可在右侧“量价预测”页计算、逐日验证和导出，另有无Qt的CLI；支持Ctrl选区末日联动、后台取消和独立研究账本。日K完成状态与2025／2026沪深日历已有保守检查；只对截至D的历史拟合预处理及模型，未来标签另行评价。

首轮三股回放仍是原始价格工程诊断，尚未系统核对公司行为，不代表真实前瞻准确率。概率字段为空、相似日频率不当作胜率。多年数据、独立封存、校准、基准／行业、完整特征和盘中模型仍未完成，不依赖Level-2采购。详见[专项设计](SHORT_HORIZON_FORECAST.md)及[验证记录](VALIDATION_FORECAST.md)。

验证采用[历史逐日预测对照](FORECAST_VALIDATION.md)：先用已有数据核对流程和小规模样本外表现，
连续滚动、另留封存测试期，并规划前瞻记录。单个历史案例不代替总体准确率，未运行的验证不填写实测结果。

## 迭代原则

- 每轮形成一个完整、可操作、可验证的工作流，再增加下一项功能。
- 参数、指标、数据源和模型通过独立边界扩展，避免在窗口类中不断增加业务分支。
- 数据事实与模型解释分开显示。对用户展示有意义的口径与状态，内部协议和调试细节保留在日志。
- 优先保证本地研究流畅和复算一致性；全市场扫描和逐笔识别单独评估负载。
- 下单交易、账户接入、付费数据采购与联网发布分别立项，不混入基础行情工作台。
