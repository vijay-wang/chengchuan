# 股票研究桌面GUI：可行性与技术选型评估

评估日期：2026-11-02。范围：先评估，不在本阶段实现GUI或购买行情服务。

## 结论

可以在现有Python分析引擎上开发个人使用的股票研究终端，实现K线、分时、成交量、指标联动，以及Ctrl拖选区间后计算特征。

第一版建议采用 **PySide6 + PyQtGraph + 现有flowradar引擎 + SQLite**。以本地Windows/Linux桌面使用为规划假设，最终安装包需要在目标操作系统上单独构建和验收。

当前目标是满足自定义研究交互。要达到大型商业行情终端的全市场数据覆盖、行情稳定性、指标体系、资讯和完整交易功能，属于更大的持续工程。

## 技术选择

| 层次 | 第一版建议 | 原因与代价 |
|---|---|---|
| 桌面窗口 | PySide6 / Qt Widgets | 窗口、快捷键、可停靠面板和后台任务可与Python引擎直接配合 |
| 图表 | PyQtGraph | 有坐标映射、联动视图、区域选择组件；需实现股票K线绘制、交易日时间轴、十字光标及指标组合 |
| 数值计算 | 现有flowradar，按实际负载再引入NumPy等 | 复用Dataset和analyze，不让界面承担分析逻辑 |
| 常规存储 | SQLite + 现有原始响应缓存 | 保存自选股、配置、选区、分析快照与常规K线；无需先部署数据库服务器 |
| Level-2扩展 | Parquet + DuckDB，按数据量评估 | 历史逐笔按日期和股票分区查询，避免把全市场逐笔一次读入内存 |
| 任务执行 | Qt后台任务；重CPU任务后续用独立进程 | 网络请求与计算不阻塞界面；线程不等于CPU计算可以无限并行 |
| 安装包 | PyInstaller或pyside6-deploy，实施时验证 | 在目标系统构建，验证字体、高DPI、数据目录与打包依赖 |

PyQtGraph官方的LinearRegionItem支持可拖动选区及选区结束信号；ViewBox支持坐标映射与视图联动。因此Ctrl框选可以在这些机制上定制，不需要自行构建全部绘图基础设施。其官方仓库也提供自定义蜡烛图示例，但该示例并非完整股票终端。

备选方案是 **Tauri + TypeScript/React + Lightweight Charts + Python侧进程**。如果后续明确需要浏览器访问、多人共享或Web界面，这条路线更值得选择。它可以利用金融图表库，但增加前后端通信、Python进程管理和跨平台打包工作。对于当前个人本地研究场景，我优先选Python桌面路线。

## 界面与Ctrl交互约定

- 左侧：自选股票、代码搜索和最近查看。
- 中央：K线／分时主图，下方成交量与指标副图，时间轴联动。
- 右侧：所选区间、基础统计、阶段候选、支持与反向证据、数据覆盖和来源。
- 顶部：股票、周期、价格口径、刷新、历史回放和导出入口。价格口径只有在数据支持时才开放切换。

操作流程：

1. 普通拖动平移，滚轮缩放；Ctrl加左键拖动建立时间选区。
2. 选区左右边界吸附到K线，显示实际起止时间、记录数和初步统计。
3. 松开鼠标后，后台运行完整区间分析，结果更新到右侧。
4. 拖动选区边界可以调整并重新计算；Esc清空。失去窗口焦点时取消未完成的拖选。
5. 从右往左选择得到同样的时间区间；价格主图和成交量副图显示相同选区。

所选对象是时间段内的完整K线，不是矩形覆盖到的部分价格。小时区间应在分钟或分时视图选择；日K图不能表达某一天内部的一小时。

拖动中只更新选区和轻量统计，避免持续触发网络与完整模型。区间不足两条记录时，显示基础信息，不运行现有阶段引擎。

指标与分析模块分别注册：输入为标准行情、时间区间和参数，输出为数值、证据及可选图表标记。第一版提供开发者新增Python分析函数的接口；直接在界面输入公式的编辑器需要另行实现。常规选区计算由本地程序完成，不必每次调用大模型。

## 与现有代码衔接

核心入口已存在：`analyze(dataset, start, end)`，位于`flowradar/core.py`。GUI新增数据服务、图表呈现、选区状态和后台任务管理，不需要把指标重新写到界面层。

建议数据流：

```mermaid
flowchart LR
    A[数据源与本地缓存] --> B[标准行情数据与时间索引]
    B --> C[K线与分时图]
    C -->|Ctrl选择实际时间区间| D[后台分析任务]
    B --> D
    D --> E[现有分析引擎]
    E --> F[结果面板与分析快照]
```

每次任务带股票、起止时间、数据版本、分析参数和请求编号。快速切换股票或选区时，旧任务返回不得覆盖新选区的结果。

图表显示范围与分析窗口独立。缩放只改变视野；保存和复算依赖真实时间及数据快照，不依赖像素位置。

## 当前数据需要补齐的部分

1. **真实分钟OHLC**：当前腾讯分钟接口提供每分钟末采样价和累计量额。可以画分时线，不能以该价同时冒充真实分钟开、高、低、收。分钟K线需要新数据源或有效导入；高低价准确性也不能通过简单合并采样价格补回。
2. **分钟历史覆盖**：当前免费接口约5个交易日。GUI本身不会增加历史覆盖，需要持续保存、历史数据源或用户导入。
3. **复权与成交额口径**：当前日线未复权。复权显示与原始成交价、成交额应分别存储，并对收益、VWAP等指标明确口径；数据不齐时不提供虚假的复权选项。
4. **交易日时间轴**：采用交易记录索引映射时间，正确处理午休、周末、停牌与不同周期，不用屏幕坐标近似推算日期。
5. **逐笔模块**：当前CSV入口只有OHLCV；未来Level-2需要单独的委托、成交、撤单适配和还原模块。图表绘制聚合行情，逐笔按所选区间查询。

## 性能证据与目标

本机使用已保存的久立真实数据，重复100次内存分析：

| 场景 | 数据集记录数 | 所选记录数 | 分析耗时中位数 | 最大值 |
|---|---:|---:|---:|---:|
| 11月2日全天分钟 | 1210 | 242 | 2.802毫秒 | 3.064毫秒 |
| 10月19日至11月2日日线 | 69 | 11 | 0.143毫秒 | 0.192毫秒 |

上述时间只包含Python内存分析，不含联网、GUI绘图、数据库、进程通信，也未评估Level-2负载，不能作为整个软件的响应时间承诺。

设计目标是缓存数据上的普通选区分析在约300毫秒内更新结果，拖动与缩放保持响应；需要在真实目标机器与GUI原型中测量。大范围数据采用按需加载、可见区绘制及分块查询，不逐条创建海量图形对象。

## 分阶段范围与工作量

以下是工程量估计，不是交付承诺。假设一名熟悉Python/Qt的开发者、个人桌面使用、目标平台可测试、数据源可用，不含购买数据等待和识别模型研究。

| 阶段 | 内容 | 粗略工作量 |
|---|---|---|
| 交互验证 | 本地真实日K／分时、成交量、Ctrl拖选、调用现有分析、验证键鼠冲突 | 2—4个开发日 |
| 个人可用首版 | 数据刷新与缓存、股票搜索、自选、多周期、结果面板、选区保存导出、异常处理和目标平台安装包 | 从启动累计约2—4周 |
| 数据与研究升级 | 稳定历史分钟、复权、回放、区间比较、经授权Level-2与算法识别 | 数据样本到位后单独评估 |

首版不把完整交易系统、全市场高频扫描、资讯终端和成熟主力识别模型包含进上述工作量。

## 验收重点

- Ctrl选择对应的时间和记录准确，缩放、反向拖动、午休和跨日不会选错。
- GUI和CLI使用同一份数据及参数时，核心指标与阶段证据一致。
- 拖动和平移不冲突；网络失败不冻结窗口；旧任务不覆盖新结果。
- 展示数据更新时间、实际覆盖、缺失项与价格口径。
- 历史回放不能取用回放时点之后的特征数据。
- 当前规则分数及机构金额字段的含义保持一致，不因换GUI而显示为已校准概率或真实持仓。
