# 0.9板块下钻与盘口逐笔工作台

日期：2026-11-04。当前体验预算保护保持，预测增强继续P2。

## 热力图窗口和板块个股

热力图具有原生最大化／最小化按钮、大小拖动及“最大化／还原”工具按钮；无窗口管理器的桌面也能填满当前屏幕，并保留还原尺寸。Ctrl＋滚轮或放大／缩小按钮缩放地图，滚动查看细小区域；“适应”恢复。文字随区域调整，完整名称和数据可在悬停、详情行或“列表视图”查看。

行业和概念区域点击后进入该板块个股列表；以板块代码查询猫爪`theme_members`，不以名称模糊猜成份。默认按**涨跌幅降序，涨幅相同时按主力净流入降序**，缺失排后。列表显示代码、名称、最新价、涨跌幅、主力净流入，可搜索及双击打开股票，返回地图不重复拉行情。

成份接口按类别一次取得并复用；行情及资金复用同日全市场`screening`，增加最新价字段。成份为当前名单，不是所选历史日名单，页面明确显示；不将它用于严格历史成份回测。板块代码来源、范围和缓存继续隔离。

## 五档、十档和队列的能力边界

右侧新增“盘口逐笔”，可展开独立工作台并最大化。提供盘口／队列、逐笔委托、逐笔还原、量价分布、原始委托分档；按当前个股及图表实际交易日读取。指数不会作为个股请求逐笔。

| 模式 | 数据及当前状态 |
|---|---|
| 读取五档 | 猫头鹰`tick`最新快照；选择1／5档，数量按股票源实测由手转股；仍受180秒缓存保护 |
| 连接实时 | `tick_v1` WSS五档合计增量；1个持续连接、最新值缓冲、UI最多10Hz合并更新。票据适配和离线模拟已验证；本机真实WSS握手返回HTTP 503，未通过实盘推送验收 |
| 历史十档 | 已发布`level2_quote_history`，可选1／5／10档，按回放时点选此前最后一个快照 |
| 委托队列 | 从已载入原始委托与成交／撤单还原的限价委托样本，可选买卖方向及第1—10档，展示最多50笔 |

普通实时接口只有五档合计价量，没有每笔排队明细；本版不把总量拆成假队列。历史源也未提供完整通道和全序号，队列按源时间／编号确定性排序，**不声称交易所完整排队优先级**。零号、重复号、已撤单、已全成和无法确认的委托不放入队列；实时快照不会混入历史队列。

历史盘口显示实际快照时间和股数。WS数量单位在文档中未明确、且本次没有收到可核定的实盘增量，先标“源数量”原值展示；不沿用HTTP快照的手转股假设。订阅票据含认证信息，只在内存中使用，不写缓存、日志或Git。关闭、切股、切源、切历史或开始回放会停止连接；错误不无限自动重连。

契约：[五档快照](https://t.meoz.cn/docs/query/stock/tick)、[实时五档订阅](https://t.meoz.cn/docs/stream/stock/tick_stream_v1)、[历史十档](https://t.meoz.cn/docs/download/level2/quote-history)。

## 原始委托分档：金额、笔数与两个饼图

右侧“资金 → 原始委托分档”及展开工作台提供同一份计算结果，买入、卖出分别展示列表与饼图。区间为：

| 档位 | 原始委托金额（元） |
|---|---|
| 0—20万 | 0＜金额＜200000 |
| 20—50万 | 200000≤金额＜500000 |
| 50—100万 | 500000≤金额＜1000000 |
| 100—200万 | 1000000≤金额＜2000000 |
| 200—400万 | 2000000≤金额＜4000000 |
| 400—600万 | 4000000≤金额＜6000000 |
| 600—1000万 | 6000000≤金额＜10000000 |
| 1000—2000万 | 10000000≤金额＜20000000 |
| 2000万以上 | 金额≥20000000 |

每张原始委托按**原价格×原数量**分档，只计一笔，不按后续成交拆成多笔。每档显示委托总金额、委托笔数及金额占比；买卖分别用各自有效委托金额作饼图分母。使用整数分计算，边界不靠浮点近似；显示百分比有四舍五入。

按本次约定：发生撤销的整张原单剔除；**部分成交后撤销剩余量也整张剔除**。这份金额包含未成交的有效原始委托，是委托名义金额，不是实际成交资金流入／流出，也不是投资者身份或持仓。

沪市样本撤单来自委托`order_type=D`；深圳样本还需处理成交记录中的`trade_code=C`。两处都读，不把撤单当成交。`exchange_order_id`与成交的`bid_order_id/ask_order_id`分别关联买、卖原单；不拿`order_id`替代零号，不拿成交编号补委托编号。

零号、重复号、成交数量超过原量等无法唯一关联的委托不计入；价格为0的市价／最优委托无法据原始字段定价，也不估价塞入某档。界面显示剔除、无价和关联缺失计数。历史数据分页未齐时，不能确认后续撤单是否已全部读到，**不发布最终金额或饼图**，以“—”和待完整状态展示。

## 逐笔、还原和量价

逐笔委托表保留源原编号、交易所委托号、类型、方向、原始价格／股数／金额。逐笔还原表每个原单一行，显示原始金额、成交股数、成交笔数和撤销／部分成交／全成／歧义状态；双击可看该原单关联成交及撤单。零号和歧义号不会展示伪造关联。

量价分布按有效成交价格聚合实际股数，分别显示源B、源S及未标方向量，附横向堆叠图与数值表。撤单记录不加入成交量。它仍保留确实发生的成交，因此与“撤单原单整张剔除”的委托统计口径不同。

“按时点回放”只使用该日期截至所选时刻的事件；未来撤单不会提前移除原单。回放在本地计算，不重复请求API。当前接口字段无法证明完整原始全序列或全交易阶段覆盖，分页结束只证明**所查询接口文件已取完**，不证明交易所所有通道无缺失。

截图：[历史盘口及队列样本](../design/chengchuan-order-book.png)、[量价分布](../design/chengchuan-price-volume.png)。设计参考[东方财富官方Level-2功能引导](https://vipmoney.eastmoney.com/commonarticle/Level2)和[同花顺官方Level-2说明](https://www.10jqka.com.cn/L2/index/function2.html)，没有照搬其机构识别宣传。

## 获取、额度、文件及性能

默认每次每类最多6页，每页10000条；可改8页。委托、成交及十档顺序查询，同一接口不并发；分页固定证券、日期和范围，原样传游标，校验重复游标、证券、日期和行数。原始页持久缓存，重新读取先复用；关闭、切证券／日期／来源可取消后台任务。数据接口为已发布历史，不能用高频重复查询冒充实时逐笔。

全走JSON分页，本轮没有消耗Parquet文件下载额度。体验每逐笔历史接口100次／日，本机继续95次保护；专业版历史范围按供应商当前契约限制为近30个自然日，实际权限由服务端决定。全日大流量超出8页时保留不完整提示，不无界翻页烧完额度。

本地可导入最多64MB／20万条的JSON数据包：`version=1`、`symbol`、`day`（YYYY-MM-DD）、`orders/trades/quotes`三组原接口字段字典数组，以及`coverage`中三组明确布尔值。未声明完整默认为不完整；完整性依据文件声明，不当作服务端独立核验。文件来源单独标为本地JSON，不能混日期或证券。本版不直接导入Parquet／券商私有格式。

批量下载在可终止进程、还原在后台计算；大表使用虚拟模型，不为每条逐笔创建一组单元格控件。当前内存只持有有界数据集，实时通道仅一个最新快照缓冲。供应商原始SQLite缓存512MB保护继续生效。

契约：[逐笔委托](https://t.meoz.cn/docs/download/level2/order-history)、[逐笔成交](https://t.meoz.cn/docs/download/level2/trade-history)。实机、算法与调用记录见[0.9验证](VALIDATION_ORDER_WORKBENCH.md)。
