# 0.11分钟显示修复与页内逐笔还原验收

日期：2026-11-05。Ubuntu 22.04／Python 3.10，Qt 6.11.3、PyQtGraph 0.14.0。需求来自分钟浮层及颜色未显示、匹配不应另弹窗的反馈。操作口径见[委托查看说明](ORDER_INSPECTION.md)。用户提供的银河证券截图作为布局参考，原图不加入仓库。

## 原因与修复

原路径：日K读取原始逐笔 → 切到分时 → 勾选颜色／分钟卡片。`open_stock`将周期变化当作完整清理，导致已经下载并还原的数据被丢弃；只勾选开关不会加载数据。之前的分钟验收直接将分析结果给图表，未覆盖这段路径。

现在同股同日切周期会暂存并在新帧确认身份后复用原逐笔及分析；切股、源、不同日期或自动刷新进入下一实际交易日会清理旧数据。勾选功能但尚未加载时，尝试后台读取对应日期的本地原始页；缓存缺失不回退联网，同一上下文失败不无限重复。缺缓存／分页未齐会在图下及悬停卡片显示原因，数值保持未发布状态。

色点从每根量柱的高度移到成交量图顶部固定色带；同一分钟的横向宽度分给多个档位，避免色点被邻近颜色覆盖。提示显示匹配分钟数，无匹配与未加载分开说明。浮层在较小画面自动紧凑显示九档，鼠标事件可穿透。

## 页内还原

“逐笔还原 → 成交还原”直接连续展示时间、价格、实际成交量、卖单和买单；手／股可切，默认最新在前。绿色卖单格和红色买单格独立按相邻的真实原单编号合并，保留实际成交时间顺序，不跨过其他编号重排数据。悬停有编号及原价、原量、累计成交、撤余状态；长合并格的数字在可见部分绘制。

原单列表保留原价、成交均价及未成交／撤单筛选；双击只在页内定位对应成交，“全部成交”复位。成交还原只含真实成交，未成交开关用于原单列表；撤单开关作用于已确认撤单关联的成交。缺失／歧义对手不补造原单。每页300行，页边界只合并本页连续段，不构造无限高的大表。

截图：[主窗口页内查看](../design/chengchuan-inline-workbench.png)、[连续卖买合并格](../design/chengchuan-inline-reconstruction.png)、[分钟卡片与顶部色条](../design/chengchuan-minute-order-signals.png)。匹配不再创建独立详情窗口；用户仍可自行展开整个盘口工作台。

## 检查结果

- 完整**223项测试通过**，本机39.438秒；新增路径覆盖周期复用、跨交易日清理、缓存一次加载／缺失提示、严格不读凭据及不访问HTTP、无十档缓存仍可计算完整原单、连续合并不重排及撤单筛选。
- 原生xcb的**20项逐笔GUI测试通过**，4.958秒；日K读取后切分时使用真正Qt鼠标移动事件经viewport／scene触发卡片，色带测试实际渲染像素颜色及不重叠位置，并验证原单定位、分页、清理及暗色隔行。
- 真实久立2026-11-04：40702条原单、35926条成交及撤单记录，其中24420笔实际成交；四种筛选组合与0.10核对金额一致。
- 原生脚本通过生产加载／后台还原流程，而非直接给图表塞分析；确认切周期保留对象，再清理后只勾选功能自动重读本地缓存，经Qt鼠标事件显示浮层。首次缓存加载、跨进程传输及还原合计约2.6秒；这不是单纯计算基准。
- 本次原生验收本机API账本**4→4，新增0次**；所有自动测试使用假源／临时缓存，本地读取分支在禁止凭据与HTTP的断言下通过。未重新测试WSS，也未消耗逐笔下载额度。
- 0.11.0 wheel构建成功，在未安装Qt的独立环境、仓库以外目录安装验收；禁止凭据和HTTP时真实缓存读取、40702原单、24420实际成交、8876340股与时间连续合并核对通过，账本不变。该wheel不是独立可执行安装程序。

运行：

```bash
.venv/bin/python -m unittest discover -s tests -v
QT_QPA_PLATFORM=xcb PYTHONPATH=tests .venv/bin/python \
  -m unittest test_microstructure_desktop -v
QT_QPA_PLATFORM=xcb .venv/bin/python -m scripts.check_order_inspection \
  --date 2026-11-04 --output-dir .chengchuan/minute-inline-native
```

本机xcb脚本复用已解包的libxcb-cursor0，仅为该进程设置LD_LIBRARY_PATH，不改系统环境。日志、运行数据库、原始数据及JSON核对结果留在Git忽略目录。Windows、高DPI和更大成交量仍需目标环境验收。

## 数据边界

该数据源的逐笔／十档仍为已发布历史，勾选开关不会凭空产生当天尚未发布的原单。无对应日期缓存时应显式读取已发布日期或导入相应JSON；不把旧日原单画到新日，也不将普通五档拆成假逐笔。分钟按提交时间归属，撤单／成交状态按回放截止时点计算，不能将全日分析当成当时已知数据。
