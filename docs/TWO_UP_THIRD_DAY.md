# 恰好连涨两天后的第三天预测（0.17）

2026-11-06，按用户确认：**必须恰好连涨两天，前一天不能上涨；允许信号不足时不预测，但必须报告覆盖率。** 普通次日预测及14:35产品入口已替换，旧内部模块只为复用、测试及历史档案审计保留。80%是验收目标，本轮尚未达成。

## 条件、目标和数据

D为第二个上涨日，要求连续四个市场交易日D−3、D−2、D−1、D都有有效行情，D−2收跌或收平、D−1及D收涨。第三天目标是D+1的正常行情涨跌；四连涨中的第三天、第四天不再作为新的“两连涨”起点。停牌、缺失或零成交不能跨过去拼接条件。

第二天必须收盘完成，沿用当日15:15来源观察及15:00报价确认；14:35无法确定全天是否收涨，因此不再提供旧盘中模式。背景股票也必须由缓存接收时间确认该日已经完成，14:00取得的日线不会因为当前已到盘后就变成收盘标签。显式无接收时间的静态研究档案只按事后重建处理，不能声称是当时接收到的数据。

每个交易日的涨跌以`close / pre_close - 1`计算。猫爪[日线契约](https://meoz.cn/docs/query/stock/daily)将`pre_close`定义为前复权可比昨收，避免现金分红或拆股的原始价格断点被误判为下跌。与图表原始OHLC不一致的缓存不会混用；缺少合法可比昨收就标“无法确认”。该字段是行情涨跌基准，不保证等同于包含所有现金流的投资总回报。

技术价格历史在每个当时前缀中向前链接：`P*_t = P*_(t−1) × close_t / pre_close_t`，当天OHLC同比例缩放，未来调整不回写更早特征。次日的可比昨收只进入事后标签，不进入D的特征。展示参考价时再换回D的实际股价尺度。成交量不因现金分红任意复权，拆股等仍可能影响原始量结构；数据是事后重建，仍可能含供应商修订。

## 模型与80%门槛

沿用63项技术、量价、支撑压力、成交分布、行为及市场特征，增加前日涨跌、第一天涨幅、第二天涨幅和加速度，共67项。模型只训练“恰好两连涨”事件；筹码和心理仍是代理，没有真实账户或持仓识别。

固定CPU候选共6组：逻辑回归C=0.1／1，深度2／3的直方图梯度提升，200棵、最大深度5、叶子最少15例的随机树，以及训练多数类基线。随机种子20261106，训练和推理限制为2个CPU线程，不使用GPU。使用[scikit-learn 1.7.2](https://scikit-learn.org/1.7/modules/ensemble.html)，梯度提升关闭随机早停验证拆分。填补与缩放只在训练数据拟合，所有股票按日期一起划分。

验证覆盖率的分母包含验证窗口内全部已成立事件，包含特征不足或真实结果缺失的事件；另外报告可用验证样本数量和比例。验证期在预设0.55／0.60／0.65／0.70／0.75／0.80／0.85／0.90阈值中选择：至少30个信号、覆盖至少10%、观察命中率至少80%，在合格方案中优先覆盖更高，再比较区间下界。得分本身不是校准概率。**没有合格方案就不发正式预测；0次预测不能计算命中率，也不能达标。**

单次桌面预测只使用D时已成熟的事件，以较早约70%事件日期训练、后约30%日期验证，边界上目标跨入验证起点的训练事件被清除。默认至少80个训练事件和40个验证事件；固定12只背景股票与当前个股的本地缓存共同提供样本，背景不足会明确提示。历史验证重新按当时可用数据选择，不把今天选出的模型回填到早期。

最终验收另看未参与选择的测试期：报告80%点估计是否达到；只有全部正式信号都有可核对真实结果、可核对信号≥100、独立目标日期≥30、覆盖≥10%，且Wilson及按目标日期分块的95%下界都≥80%，才标为通过预设统计门槛。缺失结果单独计数，并报告将其按未命中处理的保守命中率，不能靠遗漏未评价信号达标。通过后仍不能保证未来80%。窗口内股票同日相关性通过日期块处理；样本数量和覆盖条件是预先固定的研究标准。

## 操作和扩展

日K右侧“两连涨预测” → 第二天收盘日 → “预测第三天”。“回测日期与排除项”允许设置历史验证范围和异常日期；“验证事件”保留所有已成立事件，包括训练不足和拒判，统一报告分母、标签覆盖、分月／分股及同样本基线。取消和切股会终止旧任务，无自动训练循环。

```bash
# 无桌面依赖的CPU安装
python -m pip install -e '.[prediction]'
# 离线使用已经缓存的日线与可比昨收
python -m chengchuan.two_up predict --symbol 002318 --as-of 2026-11-05
python -m chengchuan.two_up backtest --symbol 002318 --start 2026-07-01 --before 2026-11-06
# 明确要求补取预先登记的研究样本时，最多3批API；重复请求复用缓存
python -m scripts.collect_two_up_data --fetch
```

原`chengchuan.forecast`与`chengchuan.nextday`命令已转向新事件任务；旧`--dataset`／`--minute-dataset`／`--mode`参数不再适用。旧原始价格实验不覆盖、不重新解释为新目标结果。新预测标识包含事件、可比涨跌目标、配置、特征及模型版本，档案保留原始行情和可比昨收。

`domain/two_up.py`为契约；`application/two_up.py`负责条件识别、因果价格、成熟标签及工作流；`two_up_learning.py`负责固定候选选择；`two_up_metrics.py`负责覆盖与验收；数据适配、界面、导出与CLI独立。仍复用旧图表、任务执行、日历、特征和研究账本，不重新复制整套软件。
